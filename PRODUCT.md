# Product

## Register

brand

## Platform

web

## Users

Primary users are game-server engineers, technical leads, and security engineers evaluating or integrating Certael. Live-operations and game-security operators are a secondary audience who need to understand how evidence, cases, economy protections, and bounded actions fit together.

## Product Purpose

The Website explains Certael without overstating what it can prove, provides a complete public documentation path from evaluation through production operation, and leads developers to a verified installation for their engine and server runtime. Success means a technical visitor can understand the trust model, choose the right components, install the suite, and find exact operational guidance without leaving the site.

## Positioning

Certael reinforces server authority with bound sessions, deterministic verification, explainable evidence, and recoverable operations while leaving game decisions with the integrating server.

## Conversion & proof

- Primary CTA: start a verified installation.
- Secondary CTA: read the documentation and inspect the source.
- The line a visitor remembers after 10 seconds: the client requests; your server decides.
- Belief ladder: Certael does not trust client claims; protected actions remain authoritative and atomic; evidence is explainable and bounded; every shipped component is versioned and verifiable; integration can be incremental.
- Proof on hand: public source, protocol contracts, compatibility manifests, release checksums, SBOMs, Sigstore bundles, CI records, engine packages, and runnable reference integrations.

## Brand Personality

Precise, assured, and restrained. The voice is technically candid: calm about limitations, specific about guarantees, and never theatrical about security.

## Anti-references

Avoid neon security-operation walls, alarm-heavy red dashboards, generic SaaS card grids, glassmorphism, decorative grids, gradient text, fake telemetry, marketing claims without a linked contract, and documentation that is merely a list of links back to GitHub.

## Design Principles

- Make the trust boundary visible before presenting features.
- Pair every claim with an inspectable artifact, protocol, or operational consequence.
- Let developers move from orientation to exact commands without changing visual language.
- Use progressive disclosure: concise overview first, complete implementation detail one level deeper.
- Treat installation, compatibility, and recovery as first-class product experiences.

## Accessibility & Inclusion

Meet WCAG 2.2 AA. Support keyboard-only navigation, visible focus, 200% text zoom, reduced motion, high contrast, narrow mobile screens, and meaning that never depends on color alone.
